# 根因分析

本案例不是工艺模型损坏。底层 MOS 能输出目标参数，但 PDK 封装器件的 CDF 没有向顶层暴露该参数。缺少映射只说明默认接口不能满足此次显示需求，并不能据此认定 Foundry PDK 有 Bug；封装、兼容性和维护策略都可能影响暴露的参数范围，具体厂商动机未确认。

记录中的三个层次：

| 层次 | 观察 | 含义 |
|---|---|---|
| 内部 MOS | 进入 Subckt 后读取到 region=2 | 底层结果提供参数 |
| example_nmos5v 的 CDF | 原有 id、vgs、vds、vth、gm，无 region | 顶层映射缺项 |
| 顶层 /NM23 | OP("/NM23" "??") 只列出原有项 | 不能仅凭顶层列表判断模型不支持 |

关键字段是 `simInfo → spectre → opParamExprList`。它把顶层名称映射到读取内部工作点的表达式；`mappedRoot()` 解析相对于封装实例的内部路径，`OP()` 读取相应工作点结果。本例已有映射使用 `.NM0.m1`，新增 region 沿用经核实的路径。

这只改变参数访问/显示映射，不改变晶体管物理模型、不创造新的仿真参数，也不会替代工作点保存。要把此诊断推广到其他器件，必须再次证明底层参数存在、顶层映射缺失且路径正确。
